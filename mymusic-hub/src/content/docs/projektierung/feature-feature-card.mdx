# 📌 Feature: FeatureCard Component

**Wofür?** Strukturierte Darstellung von Features/Aufgaben im GitHub-Issue-Stil. Jede Card zeigt: Status, ID, Titel, Kategorie, Tags, Schwierigkeit und Diskussions-Kommentare (Dev/Didaktik/Audio). Ideal für Praxis-Features, Roadmap-Items und Task-Tracking.

## 🎯 Props & Struktur

### Props

```typescript
interface Props {
  id: string;                    // z.B. "FEAT-101-A"
  title: string;                 // Feature-Titel
  status: 'Geplant' | 'In Arbeit' | 'Bereit' | 'Konzept';
  category: string;              // z.B. "Praxis 101"
  difficulty?: string;           // z.B. "Basis", "Mittel", "Fortgeschritten"
  tags?: string[];               // z.B. ['Gitarre', 'Audio', 'D1-relevant']
  comments?: Array<{
    author: string;
    role: 'Dev' | 'Didaktik' | 'Audio';
    text: string;
  }>;
}
```

## 📐 Layout-Struktur

### 1. Header (Oben)

```
[ID-Badge] [Status-Badge (farbig)] | Title | [Category-Badge]
```

- **ID-Badge:** Grau mit Monospace-Font (z.B. FEAT-101-A)
- **Status-Badge (farbig):**
  - 🟢 Bereit → Grün (#10b981)
  - 🔵 In Arbeit → Blau (#3b82f6)
  - 🟡 Geplant → Gelb (#f59e0b)
  - ⚪ Konzept → Grau (#6b7280)
- **Category-Badge:** Auf rechter Seite, hellgrau

### 2. Hauptbereich (Mitte)

`<slot />` - Beliebiger HTML/Markdown-Inhalt für:
- Feature-Beschreibung
- Teilaufgaben (Checklisten)
- Code-Beispiele
- Bilder, Videos, etc.

### 3. Tag-Zeile (Unter Hauptbereich)

Alle Tags als kleine Chips angezeigt (bei Hover: Tooltip mit Filter-Info)

```
[🎸 Gitarre] [📚 Allgemein] [🔵 D1-relevant] [Praxis]
```

### 4. Footer mit Kommentaren (Ausgeklappt)

```html
<details>
  <summary>💬 2 Kommentare (Dev: 1, Didaktik: 1)</summary>
  
  <!-- Dev Kommentare -->
  <div class="comments-section">
    <div class="comment">
      <strong>Dev</strong> - Lorem ipsum...
    </div>
  </div>
  
  <!-- Didaktik Kommentare -->
  <div class="comments-section">
    <div class="comment">
      <strong>Didaktik</strong> - Lorem ipsum...
    </div>
  </div>
  
  <!-- Audio Kommentare -->
  <!-- ... -->
</details>
```

---

## 💡 Best Practices

1. **Immer ID & Status setzen** - Das sind die kritischen Felder
2. **Tags sparsam nutzen** - Max 5-6 Tags pro Card
3. **Kommentare kurz halten** - 1-2 Sätze pro Kommentar
4. **Slot-Content strukturieren** - Mit Markdown-Überschriften
5. **Status konsistent halten** - Aktualisieren bei Fortschritt
