# Copilot Instructions für mymusic-hub

## Projekt-Überblick
- **Framework:** Astro mit Starlight
- **Sprache:** TypeScript
- **Styling:** CSS
- **Content:** MDX-Dokumente
- **Musik-Notation:** Custom Renderer (alphatab)

## Architektur & Verzeichnisse
- `src/layouts/`: Übergeordnete Layout-Komponenten (.astro)
- `src/components/ui/`: Wiederverwendbare Astro-Komponenten (reines HTML/CSS)
- `src/components/islands/`: Interaktive Framework-Komponenten (nur hier `client:*` verwenden)
- `src/content/`: MDX-Content und Konfiguration
- `src/lib/`: Utility-Funktionen, inkl. `notation-renderer.ts`

## Verifikation & Qualitätskontrolle
**Nach jeder Code-Änderung IMMER ausführen:**
```bash
npm run verify
```

Dieser Befehl führt aus:
- `biome check --write src/` — Formatiert Code mit Biome
- `astro check` — Validiert TypeScript/Astro-Syntax

**Wichtig:** Bei Fehlermeldungen:
- Repariere exakt die angegebene Zeile und den Fehlertyp
- Ändere keine unbeteiligten Dateien
- Führe niemals eigenständige Code-Formatierungen durch — Biome macht das automatisch

## Notation & Visualisierungen
- **Shared Renderer verwenden:** Alle Notation-Visualisierungen müssen den zentralen `src/lib/notation-renderer.ts` nutzen
- **Keine One-off-Komponenten:** Neue Glyphen und Positionierungsregeln gehören in den Renderer, nicht in einzelne Komponenten
- **Wiederverwendbare Komponenten:** Notation-Elemente müssen über `src/components/NotationClickable.astro` und ähnliche zentrale Komponenten gerendert werden

## Token-Effizienz
- Erstelle keine Zusammenfassungen bereits bekannter Projektdateien
- Antworte präzise und generiere nur angeforderten Code
- Nutze `npm run status` für schnelle Projekt-Übersicht (Git-Status, Dateistruktur, verfügbare Scripts)

## Workflow-Tipps
- **Für schnelle Projekt-Übersicht:** `npm run status` ausführen
- **Für Code-Format & Validierung:** `npm run verify` nach Änderungen
- **Für Entwicklung:** `npm run dev` startet den Dev-Server
- **Für Produktion:** `npm run build` erstellt optimierte Build
